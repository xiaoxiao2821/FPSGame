**Context**: After `git add .`, user got benign CRLF warnings on `.md` files (LF→CRLF on checkout, harmless on Windows).

**Note**: LFS is now active for `*.uasset/*.umap/*.png/*.map/*.zip/*.mp4`. A Git LFS remote must be configured before push, or pushes of these assets will fail.

## Build Fix: Invalid UFUNCTION specifier (UE 5.8)

**Error**: `Build.bat FPSEditor Win64 Development` exited code 6: `Unknown specifier 'BlueprintThreadSafe' found while parsing function specifiers`.

**Root cause**: The `GetAimPitch()`/`GetAimYaw()` UFUNCTION used `BlueprintThreadSafe`, which is a **class-level** specifier (for `UAnimInstance` subclasses), NOT valid on a `UFUNCTION`. UHT aborted header parsing → build failed.

**Fix applied**: Removed `BlueprintThreadSafe` from both UFUNCTION lines in `Source/FPS/FPSCharacter.h` → now `UFUNCTION(BlueprintPure, Category="Animation")`. Functions are `const BlueprintPure`, already thread-safe for AnimBP; no functional loss.

**Lesson**: In UE, `BlueprintThreadSafe` goes on `UCLASS(...)`, never on `UFUNCTION(...)`. Verify a specifier is valid for its context before using it.

## UnLua VS2026 Adaptation Fix

**Error**: `WindowsCompiler' does not contain a definition for 'VisualStudio2019'` → C# build-script compile error (CS0117), aborts whole UBT compile. UE 5.8 + VS2026.

**Root cause**: `Plugins/UnLua/Source/ThirdParty/Lua/Lua.Build.cs` `GetBuildSystem()` referenced `WindowsCompiler.VisualStudio2019`, which was **removed** from the `WindowsCompiler` enum in UE 5.5+. Confirmed UE 5.8 enum has only: `VisualStudio2022`, `VisualStudio2026` (new, latest), `VisualStudio` (= alias of 2026), plus Clang/Intel variants. VS2019 enum value no longer exists → any `== WindowsCompiler.VisualStudio2019` is a hard compile error.

**Fix applied**: Rewrote the Windows branch to match on the enum *name* via `Target.WindowsPlatform.Compiler.ToString()` instead of direct enum comparison:
- `VisualStudio2026` / `VisualStudio` → `Visual Studio 18 2026`
- `VisualStudio2022` → `Visual Studio 17 2022`
- `VisualStudio2019` → `Visual Studio 16 2019` (kept for older-engine backward compat; string never produced on UE 5.8)

**Why ToString approach**: avoids referencing a possibly-nonexistent enum member, so the .cs compiles on ANY engine version (no CS0117), and correctly maps the active VS toolchain.

**Verified generator strings** via local CMake 4.3.1 (bundled in VS2026 at `C:/Program Files/Microsoft Visual Studio/18/Community/.../cmake.exe`): `Visual Studio 18 2026` is the CMake default generator for VS2026; `17 2022` / `16 2019` also present.

**Note**: Prebuilt Lua libs exist (`lua-5.4.3/lib-c[pp]/Win64/{Debug,Release}/Lua.{dll,lib}`), so `BuildForWin64()` skips `CMake()` entirely in normal builds — the broken branch only mattered at C# compile time, not runtime. Fix makes the script compile; also future-proofs the actual CMake path if prebuilts are cleaned.
