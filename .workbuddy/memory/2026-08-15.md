## ABP_FP_Weapon GetController Null Fix

**Problem**: PIE runtime error "尝试读取非UClass中的(real)属性CallFunc_GetController_ReturnValue, 结果为无" in ABP_FP_Weapon and ABP_FP_Pistol. Error repeats every frame (9840 times in log).

**Root cause**: AnimBP EventGraph calls TryGetPawnOwner() → GetController() → GetControlRotation() → Pitch. The controller is null because weapons are activated (SetAnimInstanceClass) during character BeginPlay, before OnPossess sets the controller. Especially visible in splitscreen PIE (BP_ShooterCharacter_C_1).

**Fix applied**: Added GetAimPitch() and GetAimYaw() BlueprintPure/BlueprintThreadSafe functions to AFPSCharacter. These null-check the controller before accessing control rotation.

**Files modified**:
- Source/FPS/FPSCharacter.h — added function declarations
- Source/FPS/FPSCharacter.cpp — added function implementations
- fix_guide.md — created user guide for AnimBP modification steps

**Pending**: User needs to compile C++ and replace the GetController→GetControlRotation→Pitch chain in ABP_FP_Weapon and ABP_FP_Pistol EventGraph with GetAimPitch() call.

## Git .gitignore Fix

**Problem**: `git add .` failed with "error: open('.vs/FPS/FileContentIndex/...vsidx'): Permission denied" (also earlier "unable to index file" variant).

**Root cause**: The ignore file was named `.gitignore.txt` (Git does not recognize the `.txt` suffix), so NONE of its rules applied. `.vs/`, `Binaries/`, `Intermediate/`, `Saved/` were all untracked and scanned. `.vsidx` is locked by the running Visual Studio, so Git could not open it.

**Fix applied**: Renamed `.gitignore.txt` → `.gitignore` and added proper UE5 ignore rules: `.vs/`, `DerivedDataCache/`, `*.sln`, `*.slnx`, `.idea/`.

**Verification**: `git status --porcelain | grep .vs` returns 0; `git add -n .` no longer lists any `.vs` paths. Permission denied error gone.

**Lesson**: Always use a bare `.gitignore` (no extension) in UE projects. `.vs/` must be ignored because VS holds the `.vsidx` file open.

## .gitattributes Bug Fix (asset corruption risk)

**Context**: After `git add .`, user got benign CRLF warnings on `.md` files (LF→CRLF on checkout, harmless on Windows).

**Real bug found**: Existing `.gitattributes` line 5 concatenated patterns without spaces: `*.uasset*.umap*.png*.map filter=lfs ...` — an invalid single glob, so `.uasset`/`.umap` were NOT matched and fell under `* text=auto`, meaning Git would normalize line endings on UE binary assets → corruption risk on checkout.

**Fix applied**: Split into one pattern per line, each with `filter=lfs diff=lfs merge=lfs -text`. Verified via `git check-attr`: `.uasset` now resolves `text: unset` (binary) + LFS. Re-staged `.gitattributes`.

**Note**: LFS is now active for `*.uasset/*.umap/*.png/*.map/*.zip/*.mp4`. A Git LFS remote must be configured before push, or pushes of these assets will fail.
